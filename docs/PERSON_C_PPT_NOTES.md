# Person C 答辩要点 — 大场景一致性：NVS 回环检测 + 动态物体擦除

约 3 分 30 秒，4 页 PPT。诚实呈现：做通了什么、发现并修复了什么、卡在哪个天花板。

---

## 页 1 · 任务与方法概览（~40s）

- **我负责的"大场景一致性"模块**：①NVS 回环检测 ②动态物体擦除 ③TSDF mesh 导出（+KITTI 长序列）。
- 一句话方法：单目前端(DROID-DBA + IMU)估位姿 → 2D 高斯建图 → **回环修正全局漂移** + **动态擦除保证动态场景的鲁棒性**。
- 环境：远程 RTX 4090 + 官方 `vings_vio`(torch2.0.1/cu118);本地 5060 Ti 是 Blackwell 跑不了官方栈。

## 页 2 · NVS 回环检测（~50s）

- 机制：LightGlue 在历史关键帧里找回环 → GTSAM 位姿图修正 → 高斯地图随之搬移。
- 结果（KITTI-07，首尾回环）:**触发 10 次回环**,ATE **19.69m → 18.89m**(−4%)。
- 图:`loop_correction_compare_seq07.png`(GT / 关闭 / 开启 三条轨迹叠加)+ BEV 地图。
- 诚实点:提升不大,因为 seq07 只有 695m、漂移本就小;大回环序列(seq00/05)效果会更明显,但**S3 带宽 ~24KB/s 下不动 4GB 数据**,故用了 seq07。

## 页 3 · 动态物体擦除（核心亮点，~80s）

这是最能体现"真做了工作 + 诚实"的一页。讲三步:

1. **发现问题**:官方公开代码里动态擦除是**死代码**——`get_dynamic_mask` 从没被调用,`use_dynamic` 只触发一段会崩的调试代码。论文方法(在前端 BA 里擦)**没开源**。
2. **第一次修(走了弯路)**:我先把 mask 接进**高斯建图损失**——能擦干净地图,但**不影响位姿** → BONN 的 ATE on/off 是噪声。
3. **找到根因并修对**:把 mask 下沉到 **DROID 前端 BA 的逐边置信度 `weight`**(实测形状 `(E,2,48,64)`),让动态像素不参与位姿优化。**运行日志确认生效**。
   - **结果**:在动态最干扰前端的 `person_tracking` 上,**OFF 37.8cm → ON 28.4cm**;图 `bonn_ptrack_traj_compare.png` 里 OFF(红)冲出一段大漂移,ON(蓝)靠掩盖移动的人避免了它。
   - 配图:`bonn_ptrack_mask_*.png`(FastSAM+光流把走动的人标成动态)。
- **诚实结论**:擦除集成正确、在"动态主导前端"的序列上**确实有效**;但**不是所有 BONN 序列都稳定提升**(同窗口对比下 box2/ps tk2 无显著差异),绝对值离论文(~4cm)还远——卡在**前端精度天花板**(公开代码到不了论文 KITTI Table III,全组共有)+ 我们光流判动态偏保守。

## 页 4 · Mesh + 总结（~40s）

- **TSDF mesh**:补了官方没有的 mesh 导出(渲染深度 + Open3D ScalableTSDFVolume)→ Waymo Scene13,`tsdf_mesh.ply`(105万顶点)。
- **复现成绩单**:回环✅ / mesh✅ / 动态擦除"方法正确+单序列有效"✅ / 绝对指标未追平❌(天花板)。
- **我的贡献**:不止跑通——**定位了官方开源缺失的一环(动态擦除没接进前端)并补全 + 修复多个崩溃**,过程和局限都如实呈现。

### 备用 Q&A
- *Q:为什么 BONN 没到论文 4cm?* A:公开前端精度本身到不了论文(无官方评测 recipe,A 已查证);单目尺度不稳;我们光流判动态保守。这是天花板,不是集成错误——日志证明擦除已在前端生效。
- *Q:为什么用 seq07 不用 seq08?* A:实例到 AWS S3 带宽 ~24KB/s,4.23GB 图像下不动;seq07 同样有真实回环。
- *Q:擦除到底有没有用?* A:在动态最干扰前端的 person_tracking 上有明确效果(轨迹图可见 OFF 的大漂移被 ON 消除);不是每条序列都稳,如实说明。
